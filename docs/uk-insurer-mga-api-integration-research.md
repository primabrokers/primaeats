# UK Insurers & MGAs Offering API Integration — Research

**Date:** 2026-06-23
**Scope:** UK general insurance market. Identifies named insurers, MGAs, and enabling platforms that provide API-based integration for quoting, binding, policy administration, and claims — covering the type of API access, lines of business, and how partners/brokers connect.

---

## 1. Executive summary

API-led distribution is now mainstream in the UK. Three overlapping groups expose APIs:

1. **Direct insurer (carrier) APIs** — e.g. Aviva, ERS, Coalition, Cowbell — where the carrier exposes quote/bind/claims endpoints directly to brokers and partners.
2. **MGA APIs** — delegated-underwriting businesses (the UK has 350+ MGAs writing >10% of GI premium) that let brokers and embedded partners query product rules and bind policies via API under the MGA's own brand or the partner's brand.
3. **Enabling platforms / software houses** — the rails most UK API trading actually runs on: e-trade platforms (Acturis, Open GI, SSP, Applied/CDL), MGA policy-admin platforms (INSTANDA, Go-Insur, Insillion, Quotall), and embedded-insurance aggregators (bolttech, Qover, Bindable).

In practice, a broker rarely integrates one-to-one with each carrier; they integrate once with a software house or platform that maintains the carrier/MGA API connections. By mid-2025, industry commentary put API adoption among insurance firms at >75%.

## 3. MGAs and MGA-enablement platforms

The UK MGA sector (~£47bn market commentary; 350+ MGAs, >10% of GI premium) is heavily API-driven because MGAs need to plug their delegated products into many distribution partners.

**How MGA API integration typically works:**
- A broker integrates into the MGA's system and queries the MGA's **product rules / rating engine** via API, selling policies inside its **own software** without logging into the MGA portal.
- Or a partner sells under its **own brand**, connected by API to the MGA back end; quotes, policies, and documents are generated by the MGA product engine while the consumer only sees the partner's interface (embedded model).

**MGA / underwriting platforms that provide the APIs:**

| Platform | Role | API notes |
|---|---|---|
| **INSTANDA** | No-code product build + policy admin for MGAs (50+ MGAs) | Open-API capabilities, embedded distribution |
| **Go-Insur** (Pancentric) | MGA policy admin system | API-first, open architecture, end-to-end or integrate to third parties |
| **Insillion** | MGA distribution software | Auto-generates APIs and portals from product definitions |
| **Quotall** / **Embri** | Insurance distribution + embedded | RESTful API with live docs; create/cancel/renew new-business policies, record claims; UK-hosted, FCA-compliant |
| **SANDIS** | Insurance API platform | Quote, bind, issue, endorsements, MTAs, renewals, cancellations, status, documents, payments; sandbox, SDKs, per-partner scoped credentials, webhooks; ~2-week deployment |
| **Majesco P&C CoreConnect** | MGA/MGU core platform | API-first, microservices, London/Lloyd's market capability |
| **Guidewire** | Carrier/MGA core | Open APIs for broker platforms and embedded channels |
| **ICE-Tech** | Policy & claims platform (used by a leading UK pet insurer) | B2B APIs for partners, vet networks, comparison sites |
| **Vertafore MGA Systems**, **Buckhill** | MGA policy admin | API-based integration for underwriting/distribution |

## 4. Enabling rails: software houses & e-trade platforms

Most UK API trading flows through these intermediary systems, which maintain the carrier/MGA connections so brokers integrate once:

- **Acturis** — leading e-trade platform; builds/runs 8 of the top-10 UK insurer extranets (Insurance Times E-trading Survey 2024). Hosts API integrations including Aviva's claims API.
- **Open GI**, **SSP**, **Applied Systems**, **CDL** — the other major broker/software-house platforms supporting insurer e-trade and API connectivity.
- **Insly** — product engine MGAs/brokers use to issue quotes and documents via API (e.g. OneClickCover integrates to Insly to issue quotes and deliver docs with payment-gateway integration).

---

## 5. Embedded-insurance API aggregators

These provide a single API that fronts multiple carriers/MGAs across lines, used by retailers, platforms, and brokers to embed cover:

- **bolttech** — embed a quote, bind, and pay API into any customer journey.
- **Qover** — insurance API/integration for embedded programmes across lines.
- **Bindable** — embedded API for auto, home, condo, renters, plus ancillary pet, travel, and home warranty.

---

## 6. Coverage by line of business

- **Motor (incl. specialist/commercial/taxi):** ERS (PIERS + software houses), AXA Partners, embedded aggregators (Bindable).
- **Home / renters:** AXA Partners, Bindable, plus digital MGAs/insurtechs (e.g. Urban Jungle for tenants/flatshare).
- **Pet:** ICE-Tech-powered UK pet insurers (B2B APIs to vet networks/comparison sites); ManyPets (large UK pet insurtech).
- **Travel:** AXA Partners, embedded aggregators.
- **Commercial / SME / cyber:** Coalition, Cowbell (cyber, instant rate-quote-bind); Markel (commercial combined, MarkelTech); Superscript (digital broker model); MGA platforms (INSTANDA, Quotall, SANDIS).
- **Health / PMI:** Aviva (PMI consumer purchase API).
- **Trade credit:** Allianz Trade API.

---

## 7. How partners/brokers actually get access

1. **Insurer developer portal** — self-serve registration + sandbox (e.g. Aviva, Cowbell API registration, Coalition).
2. **Direct carrier API agreement** — appointed brokers get scoped credentials (e.g. ERS PIERS).
3. **Via a software house** — broker's Acturis/Open GI/SSP/Applied/CDL system already holds the carrier connection; the broker enables the carrier/product.
4. **Via an MGA platform** — broker/partner integrates to the MGA's product-engine API (INSTANDA, Go-Insur, Quotall, SANDIS), often white-labelled.
5. **Via an embedded aggregator** — single API across many carriers (bolttech, Qover, Bindable), typically with tiered partner programmes and 6–8 week onboarding.

---

## 8. Caveats & confidence

- The carrier landscape changes quickly; specific API endpoints and availability should be confirmed on each provider's current developer documentation before integration planning.
- Many large insurers expose API trading **only through software houses / authenticated extranets**, not public developer portals, so absence of a public portal does not mean absence of API trading.
- Figures (350+ MGAs, >10% GI premium, >75% API adoption, Acturis 8-of-top-10 extranets) are from industry commentary/surveys cited below and are directional rather than audited.
